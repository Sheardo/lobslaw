# egress-acl-generation

**Decision:** ACL is GENERATED, not hand-written. internal/egress/builder.go aggregates the role->allowed-hosts map from declared config: [[compute.providers]] endpoints become role 'llm' with those hosts; [[gateway.channels]] type=telegram becomes role 'gateway/telegram' with api.telegram.org; [[mcp.servers]] each become 'mcp/<name>'; skill manifests' network: arrays become 'skill/<name>'; clawhub config becomes 'clawhub' with clawhub.ai; fetch_url is the deliberate exception — 'fetch_url' role defaults permissive (any public host, smokescreen private-IP block on) but operators can lock it down via [compute.fetch] allow_hosts. Operators NEVER edit the ACL directly; they edit the upstream config and the ACL falls out. Regenerated on config hot-reload.

## Rationale

Hand-written ACLs drift from reality. Generated ACLs stay in sync with what the system actually does. fetch_url is permissive-by-default because it's explicitly the 'agent reaches arbitrary URLs' tool — operators who want it locked down opt in to allow_hosts; the audit log catches misuse via tool invocation records.
