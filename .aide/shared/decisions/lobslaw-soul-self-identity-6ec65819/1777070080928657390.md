# lobslaw-soul-self-identity

**Decision:** SoulConfig gains Project + Repository + Workspace fields (all optional). Rendered in the CRITICAL Identity section. New operating principle: 'When the user references the project you're running as, that's YOU' — instructs the bot to consider local filesystem (workspace path) before searching the web for similarly-named projects. Two additional CRITICAL operating principles added: (1) tool list is canonical — never claim to lack a tool that's in the function-calling schema; (2) conversation history shows your own prior actions — read it before generating apologies for things you did or didn't do.

## Rationale

Live test: bot was asked 'look at lobslaw code on GitHub' and found openclaw/openclaw (a similarly-named cousin project) instead of github.com/jmylchreest/lobslaw. Reported confidently about openclaw's CoreMemories PR as if it applied to lobslaw. The bot has no concept that 'lobslaw' IS itself. Self-identity in the prompt is the cheapest fix — operator declares the project once in SOUL.md, bot reaches for /home/x/lobslaw or github.com/jmylchreest/lobslaw on next 'look at <project>' query. Tool-list-honesty + read-your-history rules pair with the conversation-history fix to make the 'I don't have fetch_url' lie structurally impossible: the schema is in the request, the prior calls are in the thread, the bot is told to look at both.
