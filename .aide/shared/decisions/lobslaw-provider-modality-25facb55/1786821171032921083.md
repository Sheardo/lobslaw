# lobslaw-provider-modality

**Decision:** Providers are separated into DRIVERS (compiled-in wire protocols) and PROVIDERS (configured instances: label + modality + driver + endpoint + model + credential + backup), with one [[provider]] table keyed by modality and per-modality failover. chat and embedding are infrastructure; other modalities are TOOLS. IMPORTANT REVISION: the driver/provider split generalises for chat, where OpenAI compatibility is near-universal, but NOT for image/video generation — there is no de-facto standard, so a new generation provider often needs a new driver. Generation is also asynchronous (submit job, poll task, fetch expiring artifact) rather than request/response, and rides the existing AgentCommitment + scheduler machinery rather than a new job store. Billing units are per-token, per-image, per-megapixel, per-second-of-video, per-second-of-GPU or credits, so Usage carries a unit and quantity rather than only token counts. Failover has three classes, not two: transient (fall through), quota-exhausted (fall through and warn loudly), permanent (fail).
