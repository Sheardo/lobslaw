# lobslaw-provider-modality

**Decision:** Drivers (compiled-in wire protocols) separated from providers (configured instances), one [[provider]] table keyed by modality, per-modality failover in three classes (transient / quota-exhausted / permanent). chat and embedding are infrastructure; other modalities are tools. Generation is asynchronous and rides AgentCommitment + the scheduler. Usage carries a unit and quantity, not only tokens. THIRD REVISION after researching Veo and Bedrock: there is no common async protocol — the job handle must be OPAQUE to everything above the driver and polling must be a driver method, not a GET on a task URL. Artifacts arrive three ways (expiring vendor URL, inline bytes, operator-owned bucket) and the bucket mode targets an existing lobslaw storage mount. Credentials are a KIND, not a key: static bearer, gcp-service-account (short-lived OAuth, no static key possible), aws-sigv4 (per-request signing).
