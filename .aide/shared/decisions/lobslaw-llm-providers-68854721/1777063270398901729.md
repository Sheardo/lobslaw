# lobslaw-llm-providers

**Decision:** Runtime provider introspection is via the list_providers builtin (LLM-accessible) which returns {label, trust_tier, capabilities, backup} — deliberately NO model name, NO endpoint URL, NO credentials. Providers are addressed by label everywhere the bot operates (council_review, tool messaging). ProviderRegistry (compute.ProviderRegistry) is the label → client + metadata lookup shared by council_review, list_providers, and runtime backup-chain walks. Operators swap the underlying model behind a label without breaking bot behaviour or SOUL-wired references.

## Rationale

User: 'im not sure listing the specific model is really needed, just give them names (the labels) and trust tiers'. Labels are the stable handle across operator swaps (swap MiniMax-M2 behind 'main' for another model — bot reasoning still works). Model-name omission also keeps SOUL-level personality clean of implementation detail that will drift.
