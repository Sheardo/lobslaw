# egress-filter-architecture

**Decision:** Embedded smokescreen (github.com/stripe/smokescreen) running in-process on a Unix domain socket at /run/lobslaw/egress.sock. Single chokepoint for ALL outbound HTTPS — every Go http.Client and every spawned subprocess routes through it. ACL is generated at boot from live lobslaw config (compute.providers, gateway.channels, mcp.servers, skill manifests, clawhub config) and regenerated on hot-reload, NEVER hand-written. Identity via X-Lobslaw-Role HTTP header on a loopback-only listener (no spoofing risk because external processes can't reach the UDS).

## Rationale

Smokescreen is purpose-built for compromised-process egress containment, actively maintained by Stripe (commits through 2026-04), supports per-role ACLs and upstream proxy chaining for corporate networks. In-process beats sidecar for lobslaw's single-binary deployment story (works on bare-metal/systemd identically to docker), guarantees the proxy lives and dies with lobslaw (no 'proxy down, lobslaw bypasses' failure mode), and lets ACL hot-reload via in-memory config rather than file+SIGHUP. UDS over TCP eliminates port-conflict + IP-firewall threat surface. Header-based identity beats mTLS for in-process — loopback-only listener means no spoofing risk and reusing cluster CA is overkill.
