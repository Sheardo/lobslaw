# lobslaw-persistence-model

**Decision:** Two distinct persistent layers: Memory (Raft+Boltdb — agent context, episodic, and authoritative cluster artefacts) and Storage (object store — general data plus large/binary payloads). AMENDED 2026-08-15: skills are NO LONGER a storage-layer concern. Per lobslaw-skill-storage-model the cluster store is authoritative for skills; storage retains only oversized or binary skill payloads, content-addressed by a digest held on the skill record. Skill merge order remains configurable, but now orders store sources (signed / operator / agent tiers) rather than mounts. No badger in scope.

## Rationale

Clean separation between the two layers still stands, but the axis has shifted: it is no longer "agent state vs persistent objects", it is "authoritative records vs bulk payloads". Memory holds what the cluster must agree on and version; storage holds what is too large to replicate through the log. AMENDED 2026-08-15: the original "skills live in storage layer" clause is superseded by lobslaw-skill-storage-model. A skill that lives only where a mount is materialised is invisible to compute-only nodes (see the cross-cluster storage tunneling item in DEFERRED.md) and carries no version history, so backup, rollback and restore each needed their own filesystem convention. Everything else in this decision is unchanged.
