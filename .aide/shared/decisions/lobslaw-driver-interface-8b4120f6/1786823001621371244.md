# lobslaw-driver-interface

**Decision:** The provider abstraction is a narrow waist over four axes that keep changing: interaction shape, billing unit, credential kind, artifact delivery. Synchronous modalities are one method each (Chat/Embed/Describe/Transcribe/Speak). Asynchronous modalities are JobDriver{Submit, Poll, Fetch, PollInterval} where JobHandle is OPAQUE and SERIALISABLE — it holds an ARN, an operation resource name or a task id without the caller knowing which, and survives a raft round-trip because the poll may run on another node after takeover. Usage carries a Unit and Quantity with token detail as one case. Credential is Apply(ctx, *http.Request) error, which hides OAuth refresh and SigV4 signing alike. Artifact normalises URL/inline/bucket delivery into a path in a storage mount. Everything cross-cutting — retries, failover, budget, policy, tracing, artifact resolution, credential refresh — lives ABOVE the driver, so a driver does not know failover exists. External drivers are one more in-code driver that shells out to a sandboxed skill, passing the same conformance suite, not a parallel path.
