# lobslaw-retrieval-raft-only

**Decision:** All retrieval indexes and derived structures live in the Raft-replicated store. NO external vector database, NO pluggable VectorStore vtable, NO sidecar. That principle is unchanged and is reaffirmed. CORRECTED 2026-08-21: the previous version named four buckets and a prefilter as though they existed. They do not. BucketTermPostings, BucketDocStats, BucketVectorBands and BucketEmbedOutbox each have ZERO references in main, and there is no simhash anywhere in the tree. What retrieval actually is today: vector search is a linear scan over BucketVectorRecords (32 references) computing cosine per record, with a lexical fallback used whenever no embedder is configured or a query cannot be embedded. There is no approximate prefilter, no inverted index and no outbox. The SimHash band design — band values HMAC'd with the cluster MemoryKey and stored in the KEY space so a prefilter lookup is a bbolt prefix seek that never opens a sealed payload — remains the intended answer to the measured problem and is retained here as a PLAN, not a description. The rule that every derived index must be built inside FSM.Apply for the record's own log entry, never via a second raft.Apply, and must be reproducible byte-identically from a snapshot on every replica, applies to any such index when it is built.

## Rationale

The rejection of qdrant/pgvector/lancedb still holds on all four original grounds. What changed is honesty about status. A decision that describes unbuilt structures in the present tense is worse than one that says nothing: it is read as a map of the code, so a reader looking for BucketVectorBands concludes the prefilter exists and the scan cost is already solved. It is not. The measurement that motivated the design stands and is unaddressed — internal/memory/search_bench_test.go at D=1536 showed ~12.5us and ~13.9KB PER RECORD PER QUERY, so N=10000 is ~125ms and ~139MB per user message, with secretbox decrypt ~71% and proto.Unmarshal ~20% of it. The arithmetic is the smallest component, which is why the prefilter must avoid the DECRYPT rather than the maths, and why bands belong in the key space. Checked against main on 2026-08-21 before writing this. The check was not a general audit failure: lobslaw-memory-merge-architecture names FindClusters, Adjudicator, Reranker and Summarizer and all four are real (58, 28, 8 and 51 references), so this decision was the outlier rather than the pattern.

## Details

Lexical fallback landed in #165 (passive recall was entirely off without an embedder).
