# lobslaw-per-turn-budgets

**Decision:** Cost + egress budgets removed. max_tool_calls_per_turn survives as a safety valve (prevents runaway tool-call loops) but moves from [compute.budgets] to [compute.limits]. Default 30; zero disables. [compute.budgets] struct retained for back-compat but all spend/egress fields are no-ops at consumer level. Backup-provider chaining replaces cost-aware routing: free-to-use providers (cost=0 via future pricing track) can absorb fallthroughs naturally without a per-provider budget map.

## Rationale

User: 'we can just remove all budgeting, it makes it simpler'. Premature optimisation for a personal-assistant MVP. Runaway-loop protection is a safety concern (infinite tool calls) and stays. Cost budgeting adds complexity (per-provider caps, fallback semantics, spend tracking) without an actual user problem to solve yet. Can re-add later if metered providers become a real concern.
