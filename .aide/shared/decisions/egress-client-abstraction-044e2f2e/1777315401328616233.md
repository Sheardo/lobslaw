# egress-client-abstraction

**Decision:** internal/egress/ package exposes egress.Client interface (HTTPClient + Role) plus egress.For(role) and egress.ForSkill(name) factory functions. All HTTP-using code in lobslaw constructs clients via these factories — never directly via http.Client{} or http.Get(). A forbidigo lint rule in .golangci.yml blocks raw http.Client construction outside internal/egress/. The active provider is set once at node boot (egress.SetActiveProvider). Implementation is swappable without touching call sites: tomorrow we could replace embedded smokescreen with Envoy, eBPF socket filter, or no proxy at all by writing a new Provider implementation.

## Rationale

Single chokepoint guarantees egress filtering is comprehensive — every call goes through the same factory + lint rule combination ensures it stays comprehensive. Abstraction lets us evolve the implementation: smokescreen today, possibly something heavier later (Envoy if we outgrow it), or lighter (in-place library mode for Go-only deployments). Call-site code uses egress.For("llm") regardless of how filtering happens underneath.
