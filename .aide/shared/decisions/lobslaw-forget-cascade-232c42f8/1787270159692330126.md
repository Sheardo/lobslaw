# lobslaw-forget-cascade

**Decision:** UNCHANGED IN SUBSTANCE. Forget is aggressive-sweep by design: when a forget-query matches source records, any consolidated record whose SourceIDs intersect the matched set is ALSO deleted, even if other sources of that consolidation survive. PLAN.md's original spec called for re-consolidation on partial matches (keep the consolidation, drop the forgotten sources from its SourceIDs, queue a re-dream); that is still rejected, because a summary retaining one fragment of forgotten content still leaks that content. AMENDED 2026-08-21 — one half of the original rationale described something that did not exist. It argued that 'the consolidation's text AND EMBEDDING were computed from ALL sources', so the forgotten source's influence survives in both. The text half was always true and is on its own sufficient to justify the sweep. The embedding half was NOT true in practice: dream's summarizer returned a nil embedding unconditionally from the day consolidation shipped until #169 on 2026-08-20, so consolidations had no vector at all and there was no embedding to leak through. Consolidations are embedded now, which makes the original argument true going forward — but it was a prediction, not an observation, and had the sweep ever been re-litigated on the strength of it the argument would have been found hollow.

## Rationale

The conclusion needs no defending; the reasoning did. Right-to-be-forgotten is a first-class MVP requirement for a personal assistant, aggressive sweep is the privacy-safe choice, and deleted consolidations are rebuilt by the next dream run from surviving sources, so there is no permanent information loss, only a lazily-paid rebuild cost. What is corrected is that the decision cited a leak path through the summary's vector during a period when consolidations had no vector. That matters beyond tidiness: a rationale resting on an untrue premise is one a future reader can disprove, and disproving half an argument is how a correct decision gets reversed for a bad reason. Recording which half was load-bearing keeps the sweep defensible on the ground that actually held it up.

## Details

Found while fixing #169: vectorSearch was logging 'skipped records with mismatched embedding width' after a successful memory reembed, and the residue was consolidations dream had written with no vector — DreamSummarizer had no embedder and returned nil unconditionally, per a comment reasoning that a lexically-findable summary beat the nothing that existed before. True when written, since every embedder then needed an API key; falsified by the built-in embedder (see lobslaw-embeddings).
